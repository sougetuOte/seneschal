# full-review — 全体の再監査

**主人が呼んだときだけ動く。**重い手法で、私は自分からは選ばない。`disable-model-invocation: true` が、私が Skill ツールから呼ぶことを止める。
主人が呼ぶのは、たとえば次のようなときである（2026-09-24、主人の実績の証言）。

- 本当に難しいとき ── プログラムが大きくなり、モジュール単位の検収や試験では判断できない、結合部の不整合を掘る
- 目星が付かず、全体をローラーするしかないとき
- 普通に動いている物を試しに通すとき ── 裏で段階が飛ばされていた、テストを実は通っていなかった、が出たことがある

**`/code-review` とは重ならない。**あちらもパスを取れるが、毎周ゼロからの再監査のループ・実際のテスト実行・
「再監査で0件」という完了の定義を持たない（独立レビュー11回目 B11 で訂正 ── 初稿は「差分と PR が対象」と書いていた）。

## 手順

1. **下見をする（本体）。**Workflow に渡す前に次を揃える。
   - `target`：対象のパス
   - `parts`：大きければ分ける（ディレクトリ単位など）。結合部を見る gabriel だけは分けずに全体を読む
   - `testCommands`：テストと lint のコマンド。リポジトリの設定から拾う
   - `specs`：仕様の所在（`docs/specs/`、`goal.md`、README など）
   - `doNot`：`goal.md` の「やらないこと」
   - `maxRounds`：周の上限。省けば5
   **揃わなかった物は空で渡し、報告に「測っていない」と書く。**
2. **読み手が載っているかを見る。**agent 一覧に `seneschal:lens` と `seneschal:gabriel` が無ければ、止めて主人に言う（プラグインの載せ替え前）。
3. **Workflow を起動する。**`${CLAUDE_SKILL_DIR}/full-review.js` を読み、中身をそのまま `script` に、1 の object を `args` に渡す。`scriptPath` には渡さない（Workflow の `scriptPath` は、Workflow が返したパスか、作業ディレクトリか追加したディレクトリの中のファイルしか受けない。2026-09-26 に配り先で拒否された）。
4. **結果を主人へ返す。**Green か、何周したか、周ごとの指摘数とテストの結果、直さずに残した物（主人へ回した物・却下した物・主人へ回したテスト）とその理由、
   Green でないなら最後の周に残った指摘（`open`）、読まれなかった範囲。
   **commit はしない**（主人が見てから）。

## ループの形（スクリプトが持つ）

- 各周で、4体の監査とテストの実行を並列に走らせる。新しい指摘（critical と warning）が0件で、テストが通れば Green。そうでなければ修正役が直し、次の周へ
- **毎周、ゼロから全体を読む。**前の周の指摘を確かめるだけで終わらせない（修正の副作用や、他の誤りに隠れていた誤りが出る）
- **Green は「直した」ではなく「再監査で0件」である**
- 修正役が偽陽性として却下した物と、主人へ回した物は、次の周に「再指摘しない」として渡す（渡さないと、同じ境界線上の指摘が毎周出て収束しない）。
  **修正役が判断を返さなかった指摘は、捨てずに主人へ回す**
- **ゲートに当たる修正はしない。**G1・G2 と `doNot` に当たる物は、直さずに主人へ回す（ワークフローの中から主人へ問う口は無い。`core/loop.md`）。
  直せない失敗テスト（環境の都合など）も主人へ回し、次の周から失敗として数えない
- 上限は5周。届かなければ Green でないまま返す
- 監査役が1体でも落ちた周は Green にしない（覆っていない物を、覆ったと言わない）

周回の判定をモデルに任せず、スクリプトに持たせる。Opus 5.5 は長い作業の途中で進捗を報告し、そのままターンを終えることがある（公式のプロンプトガイド）。

## 観点

| 観点 | 読み手 |
|---|---|
| ソース | `seneschal:lens` |
| テスト ── 本当に走っているか、本当に検証しているか | `seneschal:lens` |
| 結合部と仕様のずれ ── スキーマ、参照、データの受け渡し、設定と実体、飛ばされた段階 | `seneschal:gabriel`（別モデルの目） |
| セキュリティ | `seneschal:lens` |

テストの実行役も `seneschal:lens`。モデルの指定は各 agent 定義の `model:` だけが持つ。
**修正役はワークフローの既定（セッションのモデル）で走る。**本体が gabriel と同じモデルで走るセッションでは、
結合部の監査役が修正役と同じモデルになる（残り3観点は別モデルのまま）。承知の上で残す。
