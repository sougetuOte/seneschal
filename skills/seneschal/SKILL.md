# seneschal — 入口

**このスキルは面接から始まる。**やりたいことを聞かされても、いきなり着手しない。
**起動名は `/seneschal:seneschal` で、ほかに同じ名前のコマンドが無ければ素の `/seneschal` でも起動する**（2026-10-10 実測。起動時の一覧には名前空間つきの名だけが出る）。
**引数を付けると本文の末尾に `ARGUMENTS:` として届く**ので、それを面接の題材にする（着手はしない）。引数が無ければ「何について？」から始める。
**引数が `条文` だけなら、面接を始めない。**下の「条文はここに無い」節の表を、パスを展開したまま示して終わる。条文の場所を引くための起動で、主人が打つことも、私が Skill ツールで起動することもある。
入口をここに置くのは、**面接だけは委譲できない**からである（ワークフローの中から主人へ問う口が無い。2026-09-11 実測）。

## 条文はここに無い

プラグインが配るのは**入口（本ファイル）と評価器（`seneschal:columba`）**、それに主人が呼ぶ重い手法
（`magi`・`full-review` と読み手 `seneschal:lens`・`seneschal:gabriel`。D31）と、条文3本（`core/`）である。
**条文を本ファイルに写さない。**写せば2箇所で保守することになる。
委任範囲と回し方は次を**読みに行く**。read-only、コピーはしない（D13 ── `SESSION_STATE.md` の決定表にある）。

| 読む物 | 何を取りに行くか |
|---|---|
| `${CLAUDE_PLUGIN_ROOT}/core/README.md` | 委任範囲の正本。3ゲートの発火点・機構・機構の所在。**「ゲートの外は止めない」節** |
| `${CLAUDE_PLUGIN_ROOT}/core/loop.md` | 回し方。**「面接（G0）」節**（問い方・省略してよいフェーズ種別）、分割・委譲・検収・キュー、止め時 |
| `${CLAUDE_PLUGIN_ROOT}/core/handoff.md` | `goal.md` の様式（3節）と SESSION_STATE の様式 |
| `${CLAUDE_PLUGIN_ROOT}/skills/magi/SKILL.md` | MAGI の手順（条文ではない）。`loop.md` の縦の停止で、Skill ツールを使わずに Read で読んで回す |

**読めなかったら主人に言う。**（作業ディレクトリの外なので、初回に許可を求められることがある。）
黙って自分の記憶で代用しない ── 条文の正本は上の3本であって、私の要約ではない。

## まず G0（面接）

問うのは3つ ── **完了条件 / 検証方法 / やらないこと**。`goal.md` に書いて**主人の承認を取る**。
承認が出るまで着手しない。問い方と省略してよい場合は `loop.md` の「面接（G0）」節にある。

**検証方法は機械で見える形にする。**columba はここを採点の物差しにする。
**ただし「時間で壊れない形」を選ぶ** ── ahead 数や未 push の状態のような、
commit や push で真偽が変わる値を物差しにすると、検収に通った直後に成果物が偽になる（2026-09-12 実測）。

## 承認が出たら

`loop.md` に従う。**検収は必ず `seneschal:columba` に出す。自分で採点しない** ──
採点した物差しは、当てた側が必ず通る。

## 消滅条件

ベンダーが面接から検収までを回すようになったら、**本ファイルごと消す。**
観測の仕方：主人へ3項を問うて承認を取る口がワークフローの内側に現れ、検収まで通ったとき。
