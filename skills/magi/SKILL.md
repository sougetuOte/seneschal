# magi — 独立エージェントの合議

**私（本体）は自分の判断ではこれを起動しない。**徹底的だが重い手法で、効率に寄った私は自分からは選ばない
（LAM の HGA 召喚記録で、自動の条件を挙げた召喚は6件あるが、6件とも主人の明示指示を併記している。条件だけで呼ばれた例は無い）。
起動は外から決める ──

1. 主人が `/seneschal:magi` を打ったとき
2. `core/loop.md` の縦の停止が発火したとき（同一フェーズで検収が2回 FAIL した）

**機構は 1 の側にしか無い。**`disable-model-invocation: true` が止めるのは、私が Skill ツールから呼ぶ経路だけである。
2 は、本体が本ファイルを Read で読んで回す ── **機構なし（プロンプト。loop.md が名指しする）。**
**縦の停止で Skill ツールを使わない。**使うとベンダーは「手順を複製せず、主人に打ってもらえ」と促す（changelog）。主人は不在である。

## 役

| 役 | 誰が | 渡す物 |
|---|---|---|
| MELCHIOR（推進） | `seneschal:lens` | ブリーフだけ |
| BALTHASAR（批判） | `seneschal:lens` | ブリーフだけ |
| CASPAR（調停） | `seneschal:lens` | ブリーフと、上の2体の出力（原文のまま） |
| gabriel（壊す） | `seneschal:gabriel` | ブリーフと CASPAR の結論。**理由付けは渡さない** |

**4役とも subagent である。本体は中継と、最後の判断だけをする。**
CASPAR を本体にしないのは、本体が gabriel と同じモデルで走るセッションがあるからである ──
そのとき、結論を書く役と壊す役が同じモデルになり、「別のモデルの目」が消える（独立レビュー11回目 A1）。
モデルの指定は各 agent 定義の `model:` だけが持つ。ここには書かない。

LAM の MAGI は3人格を同じコンテキストで合議させていた。**ここでは互いの出力を見せない** ──
批評者が提案者の理由付けを見ると、批評がその枠に乗る（`docs/design-notes.md` §7）。
CASPAR だけは2体の出力を読む。調停が仕事だからである。

## 手順

1. **ブリーフを書く。**問い・材料の所在（ファイル、URL）・制約（`goal.md` の「やらないこと」など）。
   **結論の見込みを書かない。**判断点が複数あれば点ごとに分ける。
2. **MELCHIOR と BALTHASAR を同時に呼ぶ**（Agent ツールを1メッセージで2本）。同じブリーフを渡し、
   MELCHIOR には得られる物・速さ・価値を、BALTHASAR には壊れ方・リスク・負債を出し尽くさせる。
3. **CASPAR に調停させる。**ブリーフと2体の出力を**要約せず原文のまま**渡し、結論を1つ出させる。
   **割れた点は割れたと書かせる** ── 割れは本当の争点の信号である。割れなかったことは安全の証明にならない（2体は同じモデルである）。
4. **gabriel に結論を壊させる。**渡すのはブリーフと CASPAR の結論だけ。報告ファイルのパスを渡し、
   gabriel 自身に書かせる。置き場はセッションの scratchpad（**反映したら消える前提**。決定表からそのパスを指さない）。無ければ主人に聞く。
5. **報告を読んで決める（本体）。**判定の一語で分岐しない ── 中身を読む。
   - **結論が変わる指摘**があれば、その指摘をブリーフに足して 2 からやり直す。**やり直しは1回まで。**
   - やり直した後もまた結論が変わる指摘が出たら、**主人へ渡す。**2本の報告を添える。
   - それ以外は、指摘を結論に併記して確定する。
6. **主人へ返す。**結論・割れた点・gabriel の指摘。

## 記録

結論は、使った先の決定の置き場（SESSION_STATE の決定表、ADR など）に書く。**MAGI 専用の記録簿は作らない**
（LAM では記録簿を埋める工程が抜け、計器が7週間止まっていた）。
