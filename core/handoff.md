# handoff.md — 引き継ぎの様式

**様式だけを書く。**いつ書くかは `loop.md`、保存と復帰の機構はベンダー（`/resume`・compaction・auto memory）。

本ファイルが存在する理由は**様式の正本であること**ひとつ ── 引き継ぎに何を書くかの基準をここが持つ。
**ベンダーの auto memory はリポジトリ単位で働き、
空のことがある** ── Seneschal の開発用のリポジトリでは毎セッション読まれていたが、使う側のプロジェクトの1つは9フェーズ回してなお 0 件だった
（2026-09-20 実測）。**auto memory が空のプロジェクトでは、SESSION_STATE が唯一の記憶である。**そもそもベンダーが代替するのは
保存と復帰の機構であって、様式ではない。**消滅条件：ベンダーが様式まで持つようになったら消す。**
**推測ではなく実測で書く。**置いた数値は git や ls と突き合わせてからにする。
**Seneschal の開発用のリポジトリと使う側のプロジェクトで、様式は同じ。**該当が無い節は削らず「なし」と書く。

## goal.md

G0 の承認対象で、承認後の変更は G2（主人の承認が要る）に当たる。**止める機構はプロジェクトが置く物で、置いていなければ承認後も Seneschal が書き換えられる**
（`README.md` の「使うプロジェクトの G2」節）。リポジトリの根に置く。3項だけ。`goal.md` を書けないプロジェクトでは、同じ3節を別の文書に書く（`loop.md` の面接の節）。

| 節 | 中身 |
|---|---|
| 完了条件 | 何が満たされたら終わりか |
| 検証方法 | それを誰がどう確かめるか |
| **やらないこと** | 今回の範囲外 |

3つ目が `README.md` の「ゲートの外は止めない」を成立させる。
ここが空だと、毎回確認に戻るか、毎回範囲を越えるかのどちらかになる。

**承認後に誤りが見つかったら、本文を消さずに訂正節を足す**（3項を別の文書に置いたときは、その文書に足す） ── 何を誤ったかを書き、主人の承認を取り、diff に残す。
訂正節には「この節が優先する」と書く（評価器は条文どおりに読む）。書き換えないのは**欺瞞を防ぐため**であって、
帳簿の誤記のために実装を犠牲にするためではない（開発中の試しで、主人がそう判断した）。

## SESSION_STATE.md

リポジトリの根に置く。**索引であって本体ではない。**詳細は各文書にあり、ここには置かない。**上限は200行かつ25KB。**
（ベンダーの MEMORY.md と同じ二重の上限。1行を長くして行数に収めない。数える機構は**なし**。人が見る）

| 節 | 役割 |
|---|---|
| これは何か | 初見の30秒。3〜5行 |
| 読む順序 | どの文書を何番目に読むか。行数を添える。Seneschal を使うプロジェクトでは、入口（`/seneschal:seneschal`）が読みに行く条文3本もここに入れる（入口を起動しない回にも条文が読まれるように）。場所（絶対パス）は書かず、「入口を `/seneschal:seneschal 条文` で起動すると出る表」を指す。絶対パスはプラグインの版ごとに変わり、書くとリポジトリを公開したときや移したときに、指し先の無い指示が残る |
| 現在地 | **実際に動いている物**と、まだ無い物 |
| これまで | コミットと出来事の対応表。**git log が持たない解釈だけ**を書く |
| 決定（蒸し返さない） | 番号を振る。理由は1行 |
| 採らなかった案 | 却下理由つき。再提案には新しい根拠が要る |
| 未決（主人の判断待ち） | 主人が答えるまで進まない物 |
| 未決（実測・作業待ち） | 手を動かせば決まる物 |
| 次の一手 | **1つだけ** |
| 作業の作法 | ベンダーの記憶（auto memory）にある物は書かない。**リポジトリ外から見えない物だけ**ここに置く |

**変更ファイル一覧は書かない。**git が持っている。
**未決を2種類に分ける。**混ぜると、主人を待つ必要のない物まで止まる。

## tasks.md

`docs/specs/<機能の名前>/tasks.md` に置く。同じフォルダに requirements.md（要件）と design.md（設計）を並べる形を想定しているが、条文はその2本の様式を定めない。要る規模のときに書けばよい。

- 1行1タスク、`- [ ]` / `- [x]`
- 粒度は **1タスク＝1フェーズの委譲単位**。それ以上分けられないなら大きすぎる
- フェーズ末に ☑ を付ける。全部 ☑ で release フェーズへ（`loop.md`）

## 書かないもの

| | 委譲先 |
|---|---|
| findings の様式 | Workflow の JSON schema |
| 保存・復帰の**機構** | ベンダー（`/resume`・compaction・auto memory）。**復帰後に G0 が要るかの判断は `loop.md`** |
| 数値を確かめるコマンド列 | 「実測で書く」の一行で足りる |
| compaction 復帰時の終了契約 | ベンダー。プロジェクトごとの事情を様式に持ち込まない |
